# 03 · 部署说明

## 1. 依赖

```bash
pip install -r ../requirements.txt     # opencv-python-headless, numpy, onnxruntime
```

- 需要实时窗口预览时用 `opencv-python`（而非 headless 版）。
- 加速库运行时会自动从 `onnxruntime` 的安装目录加载动态库，无需设置 PATH/LD_LIBRARY_PATH。

## 2. 运行

```bash
python stream.py --input samples/sample_01_highway_002.mp4 --csv tracks.csv
python stream.py --input samples/sample_08_tiny_033.mp4 --backend python --frames 60
python stream.py --input samples/sample_01_highway_002.mp4 --save-video out.mp4 --show
```

完整参数见 `python stream.py --help`。常用：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--backend` | native | native=加速库；python=纯 Python |
| `--imgsz` | 512 | 必须与模型匹配（512 模型不能喂 320） |
| `--max-cells` | 6 | 每帧推理块数，降它可提帧率 |
| `--threads` | 4 | 推理线程数；板端不建议超过物理核数 |
| `--flow-w` | 1.0 | 光流速度先验权重；`--no-flow` 关闭 |
| `--conf` | 0.2 | 置信度阈值（作用在 logit 上） |
| `--min-hits` / `--gate` | 5 / 0.7 | 轨迹确认帧数 / 关联门限倍率 |

## 2.1 密封通道仅飞腾派启用

`--seal-input / --seal-csv / --seal-video / --seal-key` 四个参数在 x86 上会**直接拒绝**
（退出码 2），这是设计约束：密封通道只在飞腾派上随部署启用。

如需在 x86 上做兼容性测试，加 `--force-seal`：

```bash
python stream.py --input samples/sample_08_tiny_033.mp4 --frames 4 \
  --seal-csv out --seal-key <64hex> --force-seal
```

## 2.2 输出模式与异步

```bash
python stream.py --input in.mp4 --mode csv                    # 只记 CSV（不开窗口/不写视频）
python stream.py --input in.mp4 --mode video --save-video r.mp4
python stream.py --input in.mp4 --mode show                   # 实时演示
python stream.py --input in.mp4 --mode show --async           # 异步：显示流畅、检测按能力跑
```

- `--mode` 取值 `csv|video|show|all`，`auto`（默认）按 `--show/--save-video` 推断。
- `--async` 的后台线程与 `--out-fps` 限速；**默认值由 `config.json` 的 `"async": true` 控制**，两平台一致。
- 无窗口无视频时异步自动改为逐帧阻塞，保证每帧都被处理。

## 3. 编译加速库

```bat
cd native
mingw32-make
```

产物：`native/prebuilt/satstream.dll`（Windows x64，静态链接，无外部运行时依赖，
依赖系统 UCRT，Windows 10 及以上自带）。

Linux：

```bash
cd native && make          # 产出 libsatstream.so
```

## 4. 常见问题

**Q1. `OSError: [WinError 126/127] 找不到指定的模块`**
说明加速库的依赖缺失。请确认用的是随包的 `satstream.dll`（已静态链接）；
若自行编译，链接时加 `-static`，否则会依赖 `libwinpthread-1.dll` 与 MinGW 运行库。

**Q2. `找不到可用的 onnxruntime 动态库`**
加速库通过 ctypes 之外的动态加载找 ORT 库。确认 `pip show onnxruntime` 正常，
或在 `src/native_bridge.py` 的 `_ort_dll()` 里检查路径；也可临时设置环境变量
`ORT_LIB_PATH`（自定义封装里传入 `--native-lib` 不受影响）。

**Q3. 帧率偏低**
先看单图块推理时间：x86 上 512 模型约 26.5 ms/块，320 模型 12 ms/块。
降低 `--max-cells`、换 320 模型、或减少 `--threads`（超线程会抢核）都能改善。
板端建议 4 线程 + 4~6 图块。

**Q4. 检测框抖动/跳变**
提高 `--min-hits`（例如 6）会让轨迹更晚确认但更稳；`--gate` 调小（如 0.6）会收紧关联。
光流先验保持默认开启即可，它专门用于改善快速目标的关联。

**Q5. 速度值跳**
速度已经过多滞后中值与斜率限幅，若仍跳变，检查输入视频是否为固定帧率；
`config.json` 中的 `flow_w`、`min_hits` 与 `pipeline_py.py` 顶部 `SPEED_FPS` 需要与实际帧率一致。
