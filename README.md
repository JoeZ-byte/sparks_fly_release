# 卫星视频车辆流式识别 —— Release 包

把项目流水线打包成**单文件**，对外 0 依赖：不需要项目代码、不需要数据集、
不需要配置环境（exe 版连 Python 都不需要）。

## 目录

```
release/
├─ stream_demo.exe        # ★ 单文件可执行程序（PyInstaller，免 Python）
├─ stream_demo.py         #   同源源码（放 src/，需要 Python 时用）
├─ run_demo.bat           #   双击运行 / 把视频拖到它上面
├─ requirements.txt       #   源码版需要的三个基础库
├─ model/
│  └─ a_p2_nwd_full2_raw_fp32.onnx     # 我们的 YOLO（YOLOv8n+P2+NWD，全量数据训练，12.2 MB）
└─ samples/               # 10 段样例视频（VISO 数据集片段，mp4v/10fps）
   ├─ sample_01_highway_002.mp4   1024² 高速公路立交（效果最好）
   ├─ sample_02_urban_003.mp4     1024² 城区
   ├─ sample_03~05_*.mp4          1024² 城区 ×3
   ├─ sample_06_wide_009.mp4      1024² 目标更大
   ├─ sample_07_test_010.mp4      1024² 测试段
   ├─ sample_08_quebec_048.mp4    400²  魁北克（跨来源，检测较弱）
   ├─ sample_09_doha_049.mp4      401×601 多哈（跨来源，检测较弱）
   └─ sample_10_highway2_002.mp4  1024² 高速公路另一段
```

## 使用

**方式一（exe，零依赖）**：双击 `run_demo.bat`（默认播放 sample_01），
或把任意视频文件拖到 `run_demo.bat` 上。

**方式二（源码）**：

```powershell
pip install -r requirements.txt        # numpy + opencv + onnxruntime
python stream_demo.py --input samples\sample_01_highway_002.mp4
```

常用参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `--input` | 输入视频 | 必填 |
| `--conf` | 检测置信度 | 0.35 |
| `--k` | 米/像素标定（0=不显示 km/h，只显示 px/帧） | 0.92 |
| `--fps` | 源视频帧率（测速换算用） | 10 |
| `--save out.mp4` | 把叠加结果存成视频 | 不存 |
| `--max-cells` | 每帧最多推理的图块数（算力预算） | 6 |

## 实现说明（与项目 satdet 同源）

* **运动先验**：背景差分（固定阈值 40、闭运算）→ 16 格投票 → 每帧只推理
  动静最大的 K 块；冷启动前 15 帧全图扫描。
* **跟踪**：8 态卡尔曼 + 椭圆搜索域 + 匈牙利匹配（内置实现，免 scipy）+
  暂定态转正（连续 3 帧才发 ID）+ 轨迹复活。
* **检测**：YOLOv8n+P2+NWD（**full2 模型**：26 段 / 10 万图块 / 84 万实例训练），
  图块 256→512 放大；只解码高分 anchor（后处理 115× 优化）。
* **车速**：6/12/18 帧多滞后中位差分 + EWMA(0.7) + 物理上限与限幅。
* **静止门限**：连续低速（<0.2 px/帧 ≈ 7 km/h）的目标不显示——交通流
  只关心在动的车，顺带滤掉原地晃的噪点。

## 如实说明

* **速度标签**：k=0.92 米/像素是按吉林一号量级标定的（±10%）；对 048/049
  这类异源视频请用 `--k 0`（只显示 px/帧），否则 km/h 数字不可信。
* **实时性**：本机 CPU 上 1024² 视频约 3~4 FPS（高密度场景约 3.8 FPS），
  小分辨率（048/049）约 6~7 FPS；渲染按输入帧顺序逐帧进行、不跳帧。
  显卡机器上用项目 GPU 版代码可达 20+ FPS。
* **跨来源（已大幅改善）**：048（魁北克）/049（多哈）从未参与训练，全量数据
  训练后 mAP30 从 0.29/0.18 提升到 **0.66/0.66**；但这两个场景外观仍与
  训练域不同，误检偏多属正常（详见 docs/07_算法局限与风险.md）。
* **最密场景**：022 这类 165 目标/帧的画面 mAP30 约 0.54，遮挡严重，
  是已知短板。
